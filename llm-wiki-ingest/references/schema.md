# LLM Wiki Schema

> 本文件定义了 LLM Wiki 的结构、约定和工作流程
> 最后更新：2026-04-27

---

## 🏗️ 架构概览

```
llm-wiki/
├── raw/              # 原始文档（从飞书同步）
├── wiki/             # LLM 维护的 Wiki
│   ├── index.md      # 目录索引（必须）
│   ├── log.md        # 操作日志（必须）
│   ├── entities/     # 实体页面
│   ├── concepts/     # 概念页面
│   └── sources/      # 来源总结
├── schema.md         # 本文件（配置）
└── scripts/          # 自动化脚本
```

---

## 📝 Wiki 页面约定

### 页面类型

#### 1. **来源总结** (`sources/`)
- 路径：`wiki/sources/{source-title}.md`
- 目的：单个文档的总结和关键信息提取
- 模板：

```markdown
# {文档标题}

**来源**：{飞书链接}
**摄取时间**：{YYYY-MM-DD HH:mm}
**文档类型**：{docx/bitable/sheet/等}

## 📋 核心摘要

{2-3 段落总结文档的核心内容}

## 🔑 关键要点

- 要点1
- 要点2
- 要点3

## 🏷️ 实体提及

{列出文档中提到的重要实体，链接到对应的实体页面}
- [[实体1]]
- [[实体2]]

## 💭 概念关联

{列出文档中涉及的概念，链接到对应的概念页面}
- [[概念1]]
- [[概念2]]

## 📊 数据/指标

{如果文档包含数据，提取关键指标}
- 指标1：{值}
- 指标2：{值}

## ❓ 开放问题

{列出需要进一步研究的问题}
1. 问题1
2. 问题2
```

#### 2. **实体页面** (`entities/`)
- 路径：`wiki/entities/{entity-name}.md`
- 目的：追踪特定实体（人、公司、产品等）的所有信息
- 模板：

```markdown
# {实体名称}

**实体类型**：{人/公司/产品/项目/等}
**创建时间**：{YYYY-MM-DD}
**最后更新**：{YYYY-MM-DD}

## 📝 描述

{实体的详细描述}

## 📚 信息来源

{列出所有提到该实体的文档}
- [[来源1]]
- [[来源2]]

## 📈 关键指标

{如果适用，追踪相关指标}
- 指标1：{值} ({来源})
- 指标2：{值} ({来源})

## 🔗 相关实体

{列出相关实体}
- [[相关实体1]] - {关系描述}
- [[相关实体2]] - {关系描述}

## ⚠️ 矛盾/争议

{如果不同来源的信息矛盾，记录在这里}
- 来源A说：{陈述}
- 来源B说：{陈述}
```

#### 3. **概念页面** (`concepts/`)
- 路径：`wiki/concepts/{concept-name}.md`
- 目的：解释和追踪特定概念/理论/方法
- 模板：

```markdown
# {概念名称}

**概念类型**：{理论/方法/框架/技术/等}
**创建时间**：{YYYY-MM-DD}
**最后更新**：{YYYY-MM-DD}

## 📖 定义

{概念的定义}

## 💡 核心思想

{解释概念的核心思想}

## 📚 理论基础

{列出相关的理论基础或参考文献}
- [[来源1]]
- [[来源2]]

## 🔬 应用场景

{列出概念的应用场景}
1. 场景1 - [[相关来源]]
2. 场景2 - [[相关来源]]

## ⚖️ 优缺点

**优点**：
- 优点1
- 优点2

**缺点**：
- 缺点1
- 缺点2

## 🔗 相关概念

{列出相关概念}
- [[相关概念1]] - {关系描述}
- [[相关概念2]] - {关系描述}
```

## 🔗 内部链接约定

使用 `[[页面名称]]` 格式创建内部链接：

- `[[实体名称]]` - 链接到实体页面
- `[[概念名称]]` - 链接到概念页面
- `[[来源标题]]` - 链接到来源页面
- `[[index]]` - 链接到索引页面

## 📋 工作流程

### Ingest（摄取）

**触发**：
- 用户在飞书「待处理」文件夹添加新文档
- 或者手动触发 ingest 脚本

**流程**：
1. 从飞书下载待处理文档 → `raw/`
2. 读取文档内容（使用 `feishu_fetch_doc`）
3. 生成来源总结 → `wiki/sources/{title}.md`
4. 提取实体，创建/更新实体页面 → `wiki/entities/`
5. 提取概念，创建/更新概念页面 → `wiki/concepts/`
6. 更新索引 → `wiki/index.md`
7. 记录日志 → `wiki/log.md`
8. 移动原始文档到飞书「已归档」文件夹

**日志格式**：
```markdown
## [{YYYY-MM-DD HH:mm}] ingest | {文档标题}

- 来源：{飞书链接}
- 处理时间：{HH:mm:ss}
- 新增页面：
  - [[来源页面]]
  - [[实体1]]
  - [[实体2]]
- 更新页面：
  - [[实体3]]
  - [[概念1]]
```

### Query（查询）

**触发**：
- 用户提出问题

**流程**：
1. 读取 `wiki/index.md` 找到相关页面
2. 读取相关页面内容
3. 综合信息，生成答案
4. 答案中引用来源页面

**可选**：如果答案有价值，可以创建新页面添加到 Wiki

### Lint（健康检查）

**触发**：
- 每周运行一次（Cron 任务）
- 或者手动触发

**检查项**：
1. 孤立页面：有 `[[Page]]` 链接但目标不存在
2. 过时信息：标记需要验证的页面
3. 矛盾：同一实体的不同信息
4. 缺失概念：提到但没有独立页面的概念
5. 空页面：内容不完整的页面

**输出**：生成修复建议报告

## 🔄 同步策略

### 飞书同步

**本地 → 飞书 Wiki**：
- 每小时运行一次
- 同步 `wiki/` 目录下所有 `.md` 文件（Wiki 页面）
- 同步 `raw/` 目录下所有文件（原始文档/已归档）
- 在飞书 Wiki 空间中创建目录结构：
  - `/` - 根目录
    - `index.md` - 索引页面
    - `log.md` - 日志页面
    - `schema.md` - 配置页面
    - `wiki/` - Wiki 页面
      - `entities/` - 实体页面
      - `concepts/` - 概念页面
      - `sources/` - 来源总结
    - `raw/` - 原始文档（已归档）

**飞书 → 本地**：
- 手动触发
- 从飞书 Wiki 空间拉取最新版本

### Git 版本控制

```bash
cd /workspace/projects/workspace/llm-wiki

# 初始化仓库（首次）
git init
git add .
git commit -m "Initial commit"

# 提交变更（每次 ingest 后）
git add wiki/ schema.md
git commit -m "ingest: {文档标题}"

# 查看历史
git log --oneline
```

## 🎯 质量标准

### 页面质量

- ✅ 每个页面都有清晰的标题和描述
- ✅ 所有内部链接有效（指向存在的页面）
- ✅ 引用来源时标注清楚
- ✅ 记录创建和更新时间

### 内容质量

- ✅ 信息准确，有来源依据
- ✅ 提取关键要点，避免冗余
- ✅ 交叉引用相关页面
- ✅ 标记不确定或需要验证的信息

---

## 📌 注意事项

1. **不可修改原始文档**：`raw/` 目录下的文件只读，不修改
2. **所有修改通过 Wiki**：LLM 只修改 `wiki/` 目录
3. **定期备份**：使用 Git 定期提交
4. **及时更新索引**：每次 ingest 后更新 `wiki/index.md`
5. **保持日志完整**：所有操作都记录在 `wiki/log.md`

## 🚀 快速开始

```bash
# 1. 进入目录
cd /workspace/projects/workspace/llm-wiki

# 2. 初始化 Git
git init
git add .
git commit -m "Initial commit"

# 3. 运行 ingest（处理待处理文档）
node scripts/ingest.js

# 4. 运行 query（查询 Wiki）
node scripts/query.js "你的问题"

# 5. 运行 lint（健康检查）
node scripts/lint.js

# 6. 同步到飞书
node scripts/sync.js
```
